# 任务书：GitLab / 飞书插件的失败处理改造

日期：2026-11-16。执行者：Codex。范围：`plugins/gitlab/`、`plugins/feishu/`、`worker/`（只限第 4 项）及对应测试和文档。不改 `kernel/`、`protocol/`、HTTP 协议。

开始前先读 `AGENTS.md`、`docs/protocol.md`（尤其“Agent：领活、干活、交回执”和“失败时会怎样”）、`docs/gitlab-review.md`，按其中的“怎么改”执行。

## 1. 需求

需求本身没有变：MR 被审查，本人在飞书确认评论，其余时间保持安静（协议原则 1“注意力最贵”）。现在插件出错时有三个问题，都违背了这一点：

- 卡片说不出真实原因，本人没法判断该做什么；
- 能自己恢复的临时故障被放大成长时间停摆和打扰；
- 业务上“不需要做”的情况被当成故障，反复重试。

## 3. 要做的

### 3.1 保留真实原因

- GitLab 读写（`api.ts` 的 `call` 和 `post`）、飞书命令（`review-runtime.ts` 的 `call`）、向中台发事件的 `fetch`，失败时错误文字里都要带上可诊断的原因：
  - CLI：退出码，加上 stderr 的末尾；没有 stderr 时，用 stdout 里 JSON 错误的 `type`、`code`、`message`；
  - `fetch`：`error.cause.code`，例如 `ECONNREFUSED`，以及目标主机。
- 错误文字最终会进卡片和日志，必须先脱敏，去掉 token、Authorization、`glpat-`、`u-`/`t-` 开头的飞书令牌，以及 URL 里的 query；长度在接单程序 `tail` 的 300 字内要放得下。
- 分类按原因判断，不按 JS 异常类型判断：
  - 网络不可达（连接拒绝、超时、DNS、代理连接失败、5xx、429）→ 临时；
  - 登录或权限失效 → 需要本人处理；
  - 其余 → 程序或配置错误，原样上报，不再被说成“暂时不可用”。
- `poll.ts` 里 `error instanceof TypeError` 一律算临时的那条要删掉，只认上面的网络判定。

### 3.2 业务结论不算失败

- 准入不满足（`run.ts:131`、`poll.ts:74` 及飞书审查请求路径）用“没事可做：原因”正常结束，退出码 0，不触发重派。
- 本人在飞书主动发起的请求（`origin: manual`、飞书 review）不能悄悄吞掉，要用现有的 `ask` 或 `notice` 告诉本人为什么没审。沿用 `plugins/feishu/review.ts` 里已有的卡片措辞和 key 方式，只补“不满足准入条件”这一种结局。
- 全仓搜一遍插件里其他 `throw new Error(...)` 后以退出码 1 结束的路径，逐个归入“临时 / 需要本人 / 没事可做 / bug”四类之一。归类清单写进提交说明。

### 3.3 轮询类任务不进退避

只针对 GitLab 扫描（`poll.ts` 入口）和飞书扫描（`review-runtime.ts` 的 `scan`），不涉及 review。

- 临时故障不再交 `failed`：本轮正常结束，并在 `dataRoot` 下按“实例 + 任务”记一份健康状态，包括首次失败时间、最近一次原因、连续次数。下一次 cron 就是重试。
- 连续失败持续 30 分钟以上，才用固定 key（如 `gitlab:scan-outage`、`feishu-review:scan-outage`）发一张通知，写明持续时长、最近原因，以及“恢复后自动关闭”。同一 key 的卡片还开着时不重复发。
- 恢复成功的那一轮，从 `context.open` 找到这张卡片，用 `resolve` 结案，`reason` 写恢复时间。动手前先核对协议对 `resolve` 的限制（同来源、同组、领活前已存在），以及 `done`/`nothing` 哪种结局能带 `notice` 和 `resolve`。
- 飞书扫描的游标规则不变：只有中台确认收下所有事件后才推进。
- “需要本人处理”的情况（登录失效等）保持现有的 `ask` 行为不变。

### 3.4 接单程序可不经登录 shell（兼容开关）

- 现在 `worker/worker.ts:214` 和 `worker/agents.ts:58` 固定用 `$SHELL -lc`。服务器上应该直接使用服务自己的环境；用登录 shell 会把个人 shell 里的代理和 PATH 混进来，这正是这次事故的入口。
- 在接单程序配置（`config.json` 的 `worker` 段）里加一个可选开关，名字自定，比如 `"loginShell": false`。默认保持现在的行为（macOS launchd 依赖它）；关掉后，启动和查找程序都直接使用当前进程的环境。
- 按 AGENTS.md 同步 README、README.en、INSTALL 和协议里描述接单程序环境的段落，写清 systemd 下的推荐做法：`EnvironmentFile` 加上关闭这个开关。

## 4. 不做的

- 不改内核退避和“连续 3 次”通知的逻辑，不改 HTTP 协议和 `protocol/schema.json`。
- 不合并 GitLab 扫描和飞书扫描为一个入口，那是后续的事。
- 不改审查、发布、合并的业务判断和安全边界（AGENTS.md“必须保住的事故逻辑”全部保留）。
- 不改本机或 139 的部署和配置，不运行真机脚本，不发真实飞书消息或 GitLab 评论。

## 5. 做法和验收

- 在分支 `codex/plugin-failure-handling` 上做，按 3.1～3.4 分成独立提交。每项先写失败测试，测试文件开头写明它防的失败方式；修 bug 先写复现测试。
- 用假 glab、假 lark-cli（`tests/` 里已有做法）复现第 2 节表格的前三行：
  1. 代理连不上时，卡片和日志都能看到 `proxyconnect` 或 `ECONNREFUSED` 这类真实原因；
  2. 扫描临时失败不产生 `failed`，30 分钟内不打扰本人，超过后只有一张通知，恢复后自动结案；
  3. 准入不满足不重派，飞书发起的请求能收到说明。
- 3.4：测试默认行为不变，以及关掉开关后子进程不继承登录 shell 设置的变量。
- 没改 `kernel/`、`protocol/`、`sim/` 时，跑 `npm run test:quick`、`npm run typecheck`、`npm run format:check`，全部通过。提交说明里附上实际输出的摘要。
- 现有测试是行为规格，不为迁就实现去改预期。确实需要改的，先停下，在交付说明里写清楚原因。
- 只提交，不推送，不开 PR，不部署。
